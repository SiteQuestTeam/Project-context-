# Zakres: co budujemy, a co jest tylko w pitchu (Q41)

Pojęcia: [CONTEXT.md](../CONTEXT.md). Kolejność w poziomie = kolejność budowania.

## Poziom 1: bez tego demo się nie uda

1. **Dodanie Potrzeby:** zdjęcie → rozmycie (EgoBlur) → AI: Kategoria + Poziom zagrożenia → Jednostka miejska z tabeli → ekran „Tak zobaczą to inni” z Propozycjami AI.
2. **Podobne Potrzeby + Poparcie.**
3. **Karty Sprawdzonych rozwiązań** przy nowej Potrzebie.
4. **Komentarze + Podsumowanie dyskusji.**
5. **Inicjatywa → Oferta prowadzenia → wybór Organizacji prowadzącej.**
6. **Szkic wniosku** o Inicjatywę lokalną.
7. **Mapa dla Urzędnika.**
8. **Logowanie** (e-mail / Google).
9. **Pętla:** Mieszkańcy potwierdzają „Rozwiązana” → Inicjatywa staje się Sprawdzonym rozwiązaniem. (Przesunięte z Poziomu 2: najmocniejszy argument dla HubMI.pl, a kosztuje mało.)

## Poziom 2: jeśli Poziom 1 działa

- Znaczek „Zweryfikowana” przez API KRS.
- Zakładka „Moje”, napis „czeka od N dni”, pytanie po 14 dniach.
- Moderacja tekstu, ekran Alarm 112, „Wraca” (Q32).

## Poziom 3: tylko w pitchu

- Głosowanie nad Organizacją prowadzącą.
- Powiadomienia push / e-mail.
- Logowanie przez mObywatel.
- Samodzielna rejestracja Organizacji.
- „Brak wieści od 14 dni” (Q34).
- Rozmywanie tablic, jeśli EgoBlur zawiedzie i zostanie `deface`.
